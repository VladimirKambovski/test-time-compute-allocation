## Prediction logged now, not discovered later: H4's literal accept condition is bounded by H1's small gap

Before any H4 experiment runs (Day 15, E7), flagging this now so it
reads as anticipated rather than a surprise:

H4's accept condition ("beats every fixed policy on accuracy at >=3 of 5
budget levels") is an accuracy-at-fixed-budget comparison. It is
mathematically bounded by the same oracle-vs-best-fixed gap G1 just
measured: 1-2pp on MATH-500, 0pp on OlympiadBench-A. A perfect predictor
cannot beat a fixed policy's accuracy by more than the oracle already
does -- there is only 1-2pp of accuracy on the table project-wide, per
this data. **Expectation, stated in advance:** H4's literal, primary
accept condition (beats fixed policies on raw accuracy) may also come
back weak or marginal, for the same underlying reason H1 did -- this
would not be a new, separate problem, it would be the same fact
surfacing twice. The genuinely informative result is expected to show up
in the secondary, cost-framed metrics (tokens_to_matched_accuracy,
allocation regret normalized to the random->oracle span), which measure
reaching the same accuracy for less spend rather than beating accuracy
outright. If H4 is evaluated and its primary clause fails while
tokens_to_matched_accuracy shows a large win, that should be reported as
exactly that -- a cost-efficiency win, not a disguised accuracy win --
not reframed to make the primary clause look like it passed.

Not proposing a new hypothesis for this (see below) -- H4 as worded
already covers the cost-efficiency framing; this is a heads-up about
which of H4's own clauses is likely to carry the actual finding, not a
gap in H4's design.

## Decision: NOT skipping the weaker-policy leg of G1's fallback chain

Reconsidered after review: the mechanism behind the null result (most
answers lock in by the very first sample -- the policy is already
confident and mostly correct immediately) is specifically the condition
under which the compute-optimal-TTS literature (2502.06703, one of this
project's own cited baselines) predicts LESS headroom for selection --
and predicts MORE headroom for a weaker policy, precisely because a
weaker policy is less likely to get it right on the first try. Two
consistent null results on the SAME 4B model across two benchmarks is
real evidence of benchmark-invariance. It is not evidence of
policy-strength-invariance, which is the specific axis this fallback
step exists to test. Treating the current evidence as sufficient to skip
this step would have been the wrong call -- logging that explicitly
since it's a real reversal from what was initially proposed.

**Running a cheap version instead of the full check**, per plan: ~20-30
problems, N=32 only (not also N=64), on Qwen3.5-1.7B. Full reasoning:
if this small/cheap check shows the same near-zero gap even on a noisy
sample, that's sufficient to skip the full-scale run and escalate. If it
shows something meaningfully larger, the full run becomes clearly
worth its cost before any mentor conversation happens.

## Decision: holding the action-space narrowing question until the weaker-policy result is in

SELECT's oracle win rate, computed the same way on both benchmarks (not
assumed from one): **1% on MATH-500 (1/100), 0% on OlympiadBench-A
(0/28)** -- even more extreme than the first estimate. Argument that
this ceiling can't improve with a real PRM: the pass@N proxy used here
assumes BOTH perfect (oracle) selection AND the full N=32 sample pool
for free, while a real PRM-based SELECT gets neither -- it makes
imperfect picks, and per the budget/ module's accounting rules, it buys
FEWER samples than SAMPLE at equal budget, never the full N. A real
SELECT's win rate is mathematically bounded above by what's already
measured; Day 5's real PRM integration can only confirm this ceiling or
push it lower, never reveal hidden upside. So "premature, wait for the
real PRM" is not quite the right frame for the *magnitude* question --
that part is already decidable.

**Not narrowing yet anyway** -- sequencing this after the weaker-policy
check, not before, since this change is large (reshapes E2/E5/E7 and
every downstream label) and comparatively cheap to sequence correctly
versus expensive to unwind if the weaker policy shows real SELECT-
relevant headroom that would change the calculus. If the weaker-policy
check shows nothing: proceed with narrowing to {STOP, SAMPLE, ABSTAIN},
using the exact precedent docs/brief.md already has for SEARCH ("if it
never wins, narrow to 3-way, report as a negative result"). If it shows
real headroom: reassess before narrowing anything.

Also noted for later, not acted on now: narrowing the *action space*
(SELECT rarely wins as a controller action) is a separate claim from
"the PRM is useless project-wide" -- brief.md §16 still lists PRM score
as an ablated *predictor feature* independent of whether SELECT wins as
an action. Keep these separate when the narrowing decision is written up.

## Weaker-policy check result: REAL headroom, not a null confirmation

Ran the planned cheap version: 25 MATH-500 problems (stratified
subsample of the same 100 used for the 4B check, seed 20260822), N=32,
on Qwen3.5-2B. Clean run: 800/800 succeeded first pass, zero failures,
25.7 minutes (much faster than the 4B model's runs, as expected for a
smaller model). Script: `notes/scratch/day4_generate_weaker_policy.py`,
analysis: `notes/scratch/day4_weaker_policy_analysis.py`.

**This is the "shows real headroom" branch, not the "confirms nothing"
branch.** Everything moved in the direction the compute-optimal-TTS
literature predicted for a weaker policy:

| Metric | Qwen3.5-4B (n=100) | Qwen3.5-2B (n=25) |
|---|---|---|
| STOP accuracy | 0.670 | 0.400 |
| SAMPLE accuracy | 0.730 | 0.520 |
| SELECT ceiling (pass@32) | 0.740 | 0.640 |
| **Oracle-vs-best-fixed GAP** | **1.00pp** | **12.00pp** |
| 95% bootstrap CI | [0.00, 3.00] | [0.00, 20.00] |
| SELECT-only oracle win rate | 1% | **8%** |
| Mean k* (stabilization) | 2.17 | **7.80** (median 2.0) |
| `length_truncated` rate | ~38% (N=64 pool) | **64%** |

**Caveats, stated plainly, not glossed over:**
- n=25 is small by design (this was the deliberately cheap check) -- the
  95% CI [0, 20] still touches zero, so this is NOT a clean statistical
  confirmation that G1 would pass on this policy. It IS a clear
  *directional and magnitude* signal: 12pp point estimate and an 8%
  SELECT win rate are not the same finding as 1pp/1%, by a wide margin.
- The much higher truncation rate (64% vs ~38%) is a real confound worth
  naming: some of the apparent "headroom" could partly reflect that more
  of this weaker model's samples get cut off before finishing, which
  mechanically caps STOP/SAMPLE's ability to succeed on those samples
  and could inflate the apparent gap if truncated samples would
  sometimes have been correct with more budget. Not deciding whether
  this fully, partly, or doesn't explain the gap -- flagging it as a
  live alternative explanation the full-scale check should be able to
  distinguish from genuine selection headroom (e.g. by cross-tabulating
  gap-relevant problems against truncation, the same exclusion-bias
  discipline already applied once this session).

**Decision, per the plan already committed to: NOT narrowing the action
space.** This is exactly the outcome that was supposed to trigger
"reassess before narrowing anything," not "proceed with narrowing."
Recommending the full-scale weaker-policy check (100 problems, matching
the primary check's scale, likely N=64 too given the pattern already
seen on the 4B model) before any further decision on G1's overall
verdict or the action-space question -- the cheap check has done
exactly its job by revealing enough signal to justify that further
cost, not by resolving the question outright.

## Full-scale weaker-policy check: the cheap check was noisy, not just small

Ran the full-scale version per the recommendation: reused the same 100
MATH-500 problems as the primary 4B check (the 25-problem cheap sample
was already a subset, so only the remaining 75 needed generating), N=32,
on Qwen3.5-2B. Clean run: 3200/3200 total, zero failures across both the
resumed 800 and the new 2400, 66.5 minutes for the new portion. Verified
complete (3200 unique pairs, 100 problems, all at exactly N=32) before
analyzing.

**Full comparison:**

| | Qwen3.5-4B (n=100) | Qwen3.5-2B cheap (n=25) | Qwen3.5-2B full (n=100) |
|---|---|---|---|
| STOP accuracy | 0.670 | 0.400 | 0.610 |
| SAMPLE accuracy | 0.730 | 0.520 | 0.690 |
| SELECT ceiling | 0.740 | 0.640 | 0.730 |
| **GAP** | **1.00pp** | **12.00pp** | **4.00pp** |
| 95% bootstrap CI | [0.00, 3.00] | [0.00, 20.00] | [0.00, 7.00] |
| SELECT-only win rate | 1% | 8% | 3% |
| Mean k* | 2.17 | 7.80 | 3.89 (median 1.0) |
| Oracle-action dist. | stop 67/samp 6/sel 1/abst 26 | -- | stop 61/samp 9/sel 3/abst 27 |

**The honest read: the n=25 cheap check's 12pp was optimistic noise, not
signal.** The reliable n=100 number is 4pp -- about a third of the small
sample's estimate. This is exactly the failure mode the "run the full
check before deciding" recommendation existed to catch, and it did
catch it -- had the decision been made off the cheap check alone, it
would have overstated the effect by roughly 3x.

**What the full-scale number actually says:** 4pp is a real, consistent,
literature-direction-matching effect (4x the primary 4B policy's 1pp),
but it is a modest effect, not a dramatic rescue. The 95% CI [0, 7] still
touches zero -- this does not cleanly clear G1's 8pp threshold, and it
does not cleanly confirm the null either. It sits closer to (but still
under) the 4-8pt "promote OlympiadBench" tier of G1's fallback table
than to a clean pass -- worth stating that boundary precisely rather
than rounding it toward either "passes" or "confirms nothing" when this
goes to the mentor.

SELECT-only win rate at full scale: 3% (vs. 4B's 1%, vs. the noisy
25-problem check's 8%) -- still under the 5% heterogeneity threshold
from H1's own accept condition, but closer to it, and with real sampling
noise at n=100 that a different draw could plausibly push either side
of 5%.

**Decision: not resolving either pending question (G1's overall verdict;
the action-space narrowing call) off this data alone.** Both the k*=3.89
mid-point and the SELECT-only=3% mid-point sit genuinely between the
4B's near-null result and the noisy small-sample estimate that looked
like a clear rescue. This reads as a "bring both data points to the
mentor conversation" outcome, not something to call unilaterally in
either direction. Full data (all three pools, both analysis scripts) is
in place for that conversation regardless of which way it's decided.
